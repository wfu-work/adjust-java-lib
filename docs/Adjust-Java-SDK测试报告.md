### 计时口径

使用 System.nanoTime() 包围 startAdjust(problem) 整个同步调用，包含 JSON 序列化、传输校验、JNA 转换、原生解算和 Gson 结果解析；不包含输入网络构造、结果断言、文件写入及 JVM 启动。不是纯数值分解耗时。

每个规模连续执行 18 次，前 3 次预热，后 15 次计量；中位数取排序第 8 项，最近秩 P95 取第 15 项。表中首调用是该规模首轮，不是新 JVM 冷启动。并发计时覆盖任务提交到全部完成及结果字符串比较。

未固定 CPU 频率或使用专用主机，也没有约定的性能 SLO。小样本 P95 不能外推生产尾延迟；本轮不进行峰值 RSS 或长期容量测量。构建日志中的 JVM/Byte Buddy 警告不构成测试失败。

### 参考解计算

双站非等权解析解为 x=(y1+y2/4)/1.25=(10.4,2.4,0.7) m，sigma0=sqrt(0.6)，各轴站点标准差 sqrt(0.48) m。报告对坐标、标准差、自由度及残差符号分别断言。

闭环参考程序 make_fixture.py 独立构造设计矩阵 A、权矩阵 P 与观测 y，计算 x=solve(AᵀPA,AᵀPy)、v=y−Ax、sigma0²=vᵀPv/12，站点协方差为 inv(AᵀPA)×sigma0²。它没有调用 Java SDK 或原生平差库。

闭环观测使用固定整数序列生成扰动：第 i 条基线各轴偏移为 ((3i mod 7)−3)×0.008、((5i mod 9)−4)×0.008、((2i mod 5)−2)×0.012 m，i 从 0 起算。协方差按 1+0.25i 缩放；输入、生成公式及参考答案一并保存，不使用 SDK 输出构造答案。

WGS84 参考使用 a=6378137 m、f=1/298.257223563 独立计算固定站 ECEF，再将平均 ENU 向量 (10.005,2.005,0.51) m 旋转加到原点。该比较验证坐标转换与接口语义，不验证现场控制网精度。

### 结果解释

每档预热 3 次后正式测量 15 次。全部 54 次调用正常返回，坐标与合成预期在 1e-8 m 容差内一致，sigma0 与 1 的差不超过 1e-9，整体检验全部通过。原始逐次耗时位于 probe-results.json 的 performance.measured_ms，可重新计算统计。

核心入口固定稠密求解，性能随未知坐标参数增加明显变化。star 网络的矩阵结构与一般闭环、多控制、强相关观测不同；本轮结果不能作为任意同站数站网的容量承诺。

### 64 MiB 传输边界

Java 校验允许恰好 67,108,864 个 ASCII 字节，超过 1 字节即 request_too_large；中文多字节样本也按 UTF-8 字节数拒绝。此项只调用 validateInput，输入并非合法大站网 JSON，也未传入原生解算。

因此 64 MiB 边界测试只证明传输检查，不证明 64 MiB 站网可在给定内存和时延内解算。最大性能样本为 150 站、298 基线，请求字节数见上表；本轮没有执行 5 MB 或更大的原生请求，也没有纯数值核分解计时。
